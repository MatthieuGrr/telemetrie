# Veille du samedi 31 octobre 2026

## Extension Claude Code piégée sur le Cursor Marketplace 🚨

Les versions 2.1.312 et 2.1.313 de l'extension « Claude Code for VS Code » distribuées sur le marketplace de Cursor contenaient une porte dérobée (backdoor). Dès le chargement, elle ajoutait une clé SSH de l'attaquant dans `~/.ssh/authorized_keys`, tentait d'activer sshd, s'installait pour survivre aux redémarrages et envoyait des infos sur la machine. Cursor a retiré ces versions ; la clé à rechercher porte le nom « svc-telemetry ».

[Source : phorion.io](https://phorion.io/blog/offical-claude-code-vsx-compromise/)
{ .source-link }

## PhysVLMM : des cartes qui savent comment s'ouvre une porte

Une carte de robot mobile dit **où** est une porte ou un tiroir, mais pas **comment** il réagit quand on tire dessus : PhysVLMM ajoute à la carte une estimation probabiliste de chaque articulation, réutilisée pour les tiroirs identiques pas encore touchés. Testé dans 18 vraies maisons, il identifie le type d'articulation dans 86 % des cas, contre 48 % pour la méthode de référence, et peut répondre « je ne sais pas » plutôt que de tenter son coup.

[Source : arxiv.org](https://arxiv.org/abs/2610.40539)
{ .source-link }

## socx : de la commande sous incertitude, accélérée sur GPU

C'est un solveur écrit en JAX qui découpe un gros problème de commande en plein de petits problèmes de suivi de trajectoire (LQT) résolus en parallèle sur GPU. Sur un quadrirotor, il va jusqu'à 98 fois plus vite que MOSEK et tient des horizons de 1120 pas, là où MOSEK manque de mémoire dès 320.

[Source : arxiv.org](https://arxiv.org/abs/2610.40427)
{ .source-link }

## Un drone à roues qui roule sans s'incliner

Un quadrirotor à deux roues dont les 4 hélices sont inclinées et tournent toutes dans le même sens (au lieu d'alterner). En appui sur une surface, il avance à plat, sans pencher le châssis et sans moteur d'inclinaison en plus ; l'optimisation montre que ce choix donne plus de poussée horizontale que la configuration classique.

[Source : arxiv.org](https://arxiv.org/abs/2610.40502)
{ .source-link }

## Pour le fun : un processeur de NES dans les poids d'un LLM

Dans la lignée du Qwenputer, le processeur 6502 de la NES est « compilé » directement dans les poids d'un modèle Qwen 3.5, sans aucun entraînement. Le modèle prédit l'exécution du processeur un token après l'autre, et Mario 1-1 tourne, avec une image identique pixel pour pixel à celle d'un vrai émulateur.

[Source : github.com](https://github.com/dbreunig/nesformer)
{ .source-link }

## 💡 Concept du jour : la contrainte en probabilité (« chance constraint »)

Une contrainte classique dit « ne jamais dépasser le mur ». Avec du bruit (capteurs, vent), ce « jamais » est impossible à garantir : on écrit donc plutôt « la probabilité de toucher le mur reste sous 1 % ». Le robot garde naturellement plus de marge là où il est moins sûr de sa position, comme les zones d'inflation d'une costmap Nav2, mais formalisé mathématiquement.
